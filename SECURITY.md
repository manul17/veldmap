# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in VeldMap—including credential leakage, codec memory-safety/DoS bugs (malformed GeoTIFF/JPEG 2000/NetCDF files), path traversal in downloads/caches, or TLS/signing issues—please report it responsibly rather than opening a public issue.

- Use GitHub Security Advisories ("Report a vulnerability") on the repository.
- Include reproduction steps, affected commit/version, and any crafted test input needed to verify the fix.

## Active Protections (Enforced Today)

- **Native Memory & Dependency Hygiene:** `veldmap-core`, `veldmap-raster`, `veldmap-net`, and `veldmap-app` enforce `#![forbid(unsafe_code)]`, while `veldmap-storage` enforces `forbid(unsafe_code)` on non-Windows and `deny(unsafe_code)` on Windows with scoped `#[expect(unsafe_code)]` solely for `GlobalMemoryStatusEx` FFI; `unsafe_op_in_unsafe_fn` is denied workspace-wide, and `undocumented_unsafe_blocks`, `unwrap_used`, and `expect_used` are enforced via Clippy `-D warnings` in CI. `memmap2` (outside Wayland SHM wrappers) and `openssl`/`openssl-sys` are banned in [deny.toml](deny.toml).
- **TLS, Network Caps, Redirect Safety & Input Allowlists:** Live HTTP tile, HTTP Range COG, and STAC API requests use `rustls` with the `ring` crypto provider, block insecure HTTPS-to-HTTP redirect downgrades (and refuse cross-origin redirects whenever custom auth headers are attached), reject user overrides of protocol-owned HTTP headers (`Host`, `Range`, `If-Match`, `Accept-Encoding`, `Content-Length`, `Transfer-Encoding`, `Connection`, `TE`, `Upgrade`, and STAC `Content-Type`/`Accept`), cap tile/STAC response bodies at `16 MiB` (initial pre-allocation at `256 KiB`), validate `HttpRangeSource` `Content-Range`, `Content-Encoding: identity`, strong RFC 9110 `ETag` `If-Match` / response-`ETag` integrity, and upfront `PrefetchBudget` bounds, validate `DiskTileKey` `source_key` values against a strict ASCII allowlist (`<= 128` bytes, no path separators), and reject out-of-range / `PolarCap` live URLs.
- **Private Settings, Session & Secret Redaction:** User settings (`settings.json`, which may contain Custom XYZ/TMS `api_key` or Custom STAC `auth_secret` values) and workspace sessions (`session.json`) are written atomically with owner-only `0600` permissions on Unix via `write_json_durable_private()` (backed by `write_atomic_durable_private()`); custom auth headers are marked sensitive (`HeaderValue::set_sensitive(true)`), `api_key` / `auth_secret` values, URL `user:pass@` userinfo, and query strings are redacted in `Debug` output and error messages, STAC search results restrict automatic `Bearer`/`ApiKey` headers to same-origin asset hosts without double-signing presigned URLs, and `.env*` files (except `.env.example`) are excluded by `.gitignore`.
- **Bounded Local & Cloud Raster, Vector & Tile Cache Engine (Slices 3A-1–4A):** `veldmap-raster` enforces cumulative `SinglePassIfdReader` fetch limits (`remote_ifd_limit_bytes`), fixed-schema tag caps, `MAX_IFDS`, `MAX_IFD_ENTRIES`, `MAX_SINGLE_CHUNK_BYTES` (`256 MiB`), `MAX_SOURCE_SIDE` (for untiled TIFFs, PNG, and JPEG), `png::Limits` (ignoring text/iCCP chunks and checking Adam7 whole-frame peaks), `jpeg-decoder` `set_max_decoding_buffer_size` + progressive/lossless peak checks, direct raw-chunk GeoTIFF decoding over `ByteSource` (`Planar-1/2`, `ZSTD`, `YCbCr`, `WebP`, `Palette`, RGB+NIR) with upfront decoded chunk-dimension validation, symmetric `16 MiB` `Qoi` (`MAX_QOI_DECODED_BYTES`) and checked byte-shuffled `Lz4Raw` (`VML4` header + pre-allocation bounds guard, zero `unsafe`) tile cache serialization, `MemoryBudget`/`DecodeBudgetTracker` caps, positioned `ByteSource` I/O without `memmap2`, and `TwoLaneDecodePool` worker panic isolation; read-only GeoJSON vector loads enforce regular-file validation and a `64 MiB` file-size cap.

## Planned Security Controls (Upcoming Slices)

- **Credentials & Redaction (Slice 4B):** CDSE S3 keys will live in user-local `.env` files (`0600` permissions on Unix when written via the settings UI), with mandatory redaction of credential headers and SigV4 signatures in `tracing` logs and errors.
- **Untrusted Inputs & Downloads (Slices 3C-1, 4B, 6):** Future JP2/NetCDF decoders (`3C-1`, `6`) will enforce explicit dimension, memory, and filter limits with panic isolation; resumable archive downloads (`4B`) will validate S3 path safety, persisted `ETag` `If-Range`, and exclusive `.part` file locks.
