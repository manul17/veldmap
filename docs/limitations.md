# Known Limitations

Explicit scope boundaries and current implementation limits of VeldMap. Entries are updated as slices close and capabilities land.

## Planetary Model & Platform (Committed v1 Scope)

- **Flat WGS84 ellipsoid (no 3D DEM mesh displacement in v1; nadir camera currently):** VeldMap v1 renders a smooth WGS84 ellipsoid (`height = 0.0`) with a nadir camera ([Design Decisions](decisions.md)). Terrain relief is delivered as quantitative GPU layers (hillshade, slope, aspect) in Slice 5B-1 rather than 3D vertex displacement, avoiding renderer-induced relief parallax and keeping uniform nadir GSD for orthophoto alignment, split-screen swipe, and temporal diffing. (Source-imagery relief distortion in non-orthorectified swaths is unaffected.)
- **Desktop native GPU backends only (Vulkan, DirectX 12, Metal):** VeldMap restricts `wgpu` to native primary desktop backends (`Backends::PRIMARY` minus `BROWSER_WEBGPU`), intentionally excluding OpenGL/GLES and browser WASM to keep Reverse-Z, `view_formats`, and `R32Float` behavior uniform across platforms. Systems without hardware Vulkan/DX12/Metal drivers require a software fallback such as Mesa Lavapipe or Microsoft WARP.

## Current Milestone Limits (Post-Slice 3A-1a)

- **Planetary basemaps (bundled offline + live HTTP); headless GeoTIFF engine landed, UI draping upcoming:** Slice 2B delivers async HTTP live basemap streaming (NASA GIBS Blue Marble `GoogleMapsCompatible_Level8`, NASA GIBS VIIRS True Color `GoogleMapsCompatible_Level9` with explicit UTC date, EOX Sentinel-2 Cloudless `max_level = 14` with CC BY 4.0 attribution, and Custom XYZ/TMS URL/API-key templates) backed by a bounded SQLite WAL LRU disk cache, CPU linear-light mipmaps, and seamless offline/polar fallback to bundled NASA Blue Marble (`z = 0..3`). Slice 3A-1a has landed the headless local GeoTIFF/BigTIFF/COG engine (`ByteSource`, `LocalFileSource`, `LocalFingerprintCache`, `MemoryBudget`, `TileScheduler`, `TiffSource`, `SharedChunkCache`, `TwoLaneDecodePool`); user-facing local file opening, GPU warp-mesh draping, PNG/JPEG overlays, and QOI disk caching land in Slice 3A-1b, geodesic measurement tools land in Slice 3A-2, and zero-auth STAC/COG streaming lands in Slice 4A (see [plan.md](../plan.md)).
- **Navigation & viewport controls:** Interactive controls currently cover primary-button drag orbit, scroll/pinch zoom-at-cursor, Go-To DD/DMS/MGRS, live/offline/ellipsoid basemap switching & settings, graticule toggle, and `N`/compass Reset-North. Manual heading rotation, keyboard pan/zoom, and multi-viewport split panes are not yet implemented.
- **CRS, datum shifts & MGRS coverage:** `veldmap-core::geo::projection` currently supports WGS84 UTM (`326xx`/`327xx`), Gauss-Krüger on Pulkovo 1942 (`284xx`), MSK-61 (`6336101..=6336103`), and Web Mercator (`3857`) using static 7-parameter Helmert datum shifts (horizontal only; no grid-based shifts such as NADCON5/NTv2/OSTN15 or WKT2 projections yet—datasets on tectonic/grid-shifted datums may retain decimetre-to-metre offsets relative to WGS84/ITRF). ETRS89/NAD83 UTM, LAEA Europe (`3035`), Polar Stereographic (`3413`/`3031`), LCC (1SP/2SP), Albers Equal Area (`5070`), Sinusoidal, explicit Helmert rotation conventions, user-defined TM parameters, and world files land in Slice 3A-2. MGRS parsing covers UTM bands `C`–`X` (including Norway `31V`/`32V` and Svalbard `31X`/`33X`/`35X`/`37X` bounds), excluding UPS polar zones (`A`, `B`, `Y`, `Z`).
- **Default UI fonts only:** Only `eframe`'s built-in default fonts are loaded until UI polish, limiting glyph coverage for non-Latin scripts in file paths or metadata.
- **Basemap settings persisted; workspace sessions & CDSE credentials upcoming:** Basemap selection, NASA GIBS date, Custom XYZ/TMS config, graticule toggle, and disk cache budget persist durably to `settings.json` via `write_json_durable_private()` (`0600` on Unix). Full multi-layer workspace sessions land in Slice 5A and CDSE credentials (`ProjectDirs/.env`) land in Slice 4B; GPU/logging overrides remain controlled via environment variables (`RUST_LOG`, `WGPU_BACKEND`, `WGPU_POWER_PREF`).
