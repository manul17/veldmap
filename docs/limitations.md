# Known Limitations

Explicit scope boundaries and current implementation limits of VeldMap. Entries are updated as slices close and capabilities land.

## Planetary Model & Platform (Committed v1 Scope)

- **Flat WGS84 ellipsoid (no 3D DEM mesh displacement in v1; nadir camera currently):** VeldMap v1 renders a smooth WGS84 ellipsoid (`height = 0.0`) with a nadir camera ([Design Decisions](decisions.md)). Terrain relief is delivered as quantitative GPU layers (hillshade, slope, aspect) in Slice 5B-1 rather than 3D vertex displacement, avoiding renderer-induced relief parallax and keeping uniform nadir GSD for orthophoto alignment, split-screen swipe, and temporal diffing. (Source-imagery relief distortion in non-orthorectified swaths is unaffected.)
- **Desktop native GPU backends only (Vulkan, DirectX 12, Metal):** VeldMap restricts `wgpu` to native primary desktop backends (`Backends::PRIMARY` minus `BROWSER_WEBGPU`), intentionally excluding OpenGL/GLES and browser WASM to keep Reverse-Z, `view_formats`, and `R32Float` behavior uniform across platforms. Systems without hardware Vulkan/DX12/Metal drivers require a software fallback such as Mesa Lavapipe or Microsoft WARP.

## Current Milestone Limits (Post-Slice 2A)

- **Bundled offline basemap only (`z = 0..3`); live streaming & local rasters upcoming:** Slice 2A bundles a public-domain NASA Blue Marble Next Generation equirectangular basemap (`3600 x 1800`, served as virtual `z = 0..3` `Geodetic` tiles + `z = 0..1` Polar Stereographic cap tiles with decoupled `z_geom <= 16` geometry and procedural `fwidth()` graticule). Live HTTP basemaps (NASA GIBS / EOX Sentinel-2 Cloudless) and bounded disk caching land in Slice 2B; local GeoTIFF/BigTIFF/COG/PNG/JPEG overlays and geodesic measurement tools land in Slices 3A–3B (see [plan.md](../plan.md)).
- **Navigation & viewport controls:** Interactive controls currently cover primary-button drag orbit, scroll/pinch zoom-at-cursor, Go-To DD/DMS/MGRS, `Satellite / Ellipsoid-only` basemap switching, graticule toggle, and `N`/compass Reset-North. Manual heading rotation, keyboard pan/zoom, and multi-viewport split panes are not yet implemented.
- **CRS, datum shifts & MGRS coverage:** `veldmap-core::geo::projection` currently supports WGS84 UTM (`326xx`/`327xx`), Gauss-Krüger on Pulkovo 1942 (`284xx`), MSK-61 (`6336101..=6336103`), and Web Mercator (`3857`) using static 7-parameter Helmert datum shifts (horizontal only; no grid-based shifts such as NADCON5/NTv2/OSTN15 or WKT2/LCC/Albers projections yet—datasets on tectonic/grid-shifted datums may retain decimetre-to-metre offsets relative to WGS84/ITRF). ETRS89/NAD83 UTM, LAEA Europe (`3035`), Polar Stereographic (`3413`/`3031`), user-defined TM parameters, and world files land in Slice 3A-2. MGRS parsing covers UTM bands `C`–`X` (including Norway `31V`/`32V` and Svalbard `31X`/`33X`/`35X`/`37X` bounds), excluding UPS polar zones (`A`, `B`, `Y`, `Z`).
- **Default UI fonts only:** Only `eframe`'s built-in default fonts are loaded until UI polish, limiting glyph coverage for non-Latin scripts in file paths or metadata.
- **No persistent workspace or credentials UI yet:** Runtime configuration is currently controlled via environment variables (`RUST_LOG`, `WGPU_BACKEND`, `WGPU_POWER_PREF`).
